## 3. Marker A/B verdict (Phase 2 deliverable)

**Verdict: NULL EFFECT.** Markers as currently configured (`low_redundant`=0.5x,
`low_review_pending`=0.75x on 203 sources) provide no statistically detectable
benefit on this 71-query suite, and slightly hurt aggregate NDCG@10 (-1.8%
relative, not significant).

**Per-domain NDCG@10 deltas** (markers ON minus markers OFF):

| Domain | n | NDCG ON | NDCG OFF | Δ | Notes |
|---|---:|---:|---:|---:|---|
| **mathematics** (heavy markers) | 2 | 0.514 | 0.514 | **0** | No marked source surfaces in top-K; downweight inactive |
| **analysis** (heavy markers) | 2 | 0.644 | 0.644 | **0** | Same |
| **causal_inference** (clean) | 4 | 0.670 | 0.670 | **0** | Same (no markers in CI domain) |
| **machine_learning** | 1 | 0.992 | 0.992 | **0** | Single XGBoost query — top results from non-marked sources |
| **software_engineering** | 1 | 0.764 | 0.764 | **0** | Same |
| **cross_domain** | 10 | 0.378 | 0.387 | **-0.009** | Slight regression — marked sources surface in mixed queries and get penalized |
| **reinforcement_learning** | 3 | 0.559 | 0.621 | **-0.062** | Notable regression — marked source(s) surface in RL retrievals |
| **dynamical_systems** | 2 | 0.801 | 0.951 | **-0.150** | Largest regression — marked source(s) likely from chaos/intro books getting penalized |
| **biology_neuroscience** | 1 | 0.873 | 1.000 | **-0.127** | Regression on single query |
| (other 26 domains) | varies | varies | varies | 0 | No marker effect |

**Why null on the targeted domains**:
1. The math + analysis queries in `v2_queries.yaml` ("analytic number theory
   prime number theorem Dirichlet", "calculus integration techniques fundamental
   theorem", "Banach space functional analysis operator", "complex analysis
   Cauchy integral formula") surface canonical references in their top-K. These
   canonical references are NOT marked `low_redundant` — Schaum's outlines and
   freshman-calc parts (the marked sources) appear deeper in the ranking, below
   top-10. So the multiplier never operates on a top-10 chunk.
2. The marker-stress-test queries the user actually cares about — "how does X
   handle Y assumption", queries that would pull from generic intro books — are
   not in the v2 fixture. The fixture is biased toward queries that already
   discriminate well.

**Where markers HURT**: in 3-4 domains (RL, dyn_sys, bio_neuro, cross_domain),
the markers caused regression. Investigation needed: are these legitimately
marked sources being penalized for in-domain queries (mistagged source/domain
relationship) or sources marked low_redundant that are actually relevant for
RL/dyn_sys queries?

**Caveat — label quality**: §4 audit found 53% of grade-0 labels are wrong
(false-negatives). If a marker downweights a chunk that auto-grader scored 0
but is actually relevant, the eval CORRECTLY penalizes the marker. If a marker
downweights a chunk auto-grader scored 0 that IS irrelevant, the eval falsely
credits the marker as harmful. Net: the eval cannot reliably distinguish marker
effect from label noise on this suite. **Re-grading is required before re-running**.

**Decision**:
- ✗ Do NOT scale markers to 400+ in Session +2 based on this null result alone.
  The eval suite is the wrong test (wrong queries + bad labels) for the
  hypothesis "markers improve retrieval on polluted domains".
- ⚠ Investigate the dynamical_systems / reinforcement_learning regressions
  (-0.15 / -0.06 NDCG@10): identify which marked sources are surfacing for
  those queries and whether the markers are mistakes for that domain (a source
  marked `low_redundant` because of duplicate calc content might also be
  mistagged with `dynamical_systems`).
- → Path forward: build a marker-stress-test query set whose top-K results
  intentionally include marked sources, with human-graded relevance, then
  re-run A/B. Until then, the 0.5/0.75 multipliers are placeholders without
  empirical support.

## 4. Ground-truth label trust (Phase 3 deliverable)

**Audit**: 60 samples (5 grade-3 + 5 grade-0 × 6 marker-stress-test domains).
Source: `fixtures/eval/v2_pool_audit_2026-05-05.yaml`.

| Stratum | Strict hit-rate | Lenient hit-rate | Threshold |
|---|---:|---:|---:|
| Grade 3 (top relevance) | 25/30 = 83% | 30/30 = 100% | ≥80% |
| Grade 0 (irrelevance)   | 11/30 = 37% | 14/30 = 47%  | ≥80% |

**Verdict**: `REJECT_AUTO_GRADES`. Grade-0 fails dramatically: ~50% of samples flagged
"irrelevant" by the auto-grader were actually relevant chunks (false-negatives).
This is the canonical failure mode where similarity-threshold heuristics miss
in-domain canonical references (Spirtes DAGs, Reed-Simon spectral theorem,
LightGBM-as-XGBoost-peer).

**Implication for §2-3 numbers**: NDCG/MRR computed against these labels are
**pessimistic** relative to true retrieval quality. A/B comparisons (markers on
vs off) remain informative because the noise is constant; absolute values are not.

See also: `feedback_eval_label_quality.md` memory for failure mode taxonomy +
re-grading recommendations.

## 6. Decisions for next sessions

**Updated based on the null A/B verdict + label-quality finding:**

1. **Marker extension to 400+ (was Session +2): DEFERRED until eval-trust is
   established.** No empirical evidence the existing 203 markers help; scaling
   without that evidence is risky. Revisit after step 3.
2. **Multiplier retuning (0.3/0.6 vs 0.7/0.85 vs RRF): DEFERRED.** Same reason —
   we can't tune without a trustworthy signal.
3. **Investigate the dynamical_systems / reinforcement_learning / cross_domain
   regressions** before any further marker work. Concretely:
   - For each query in those domains, list the markers that appeared in top-30 results.
   - Check whether the marked sources are mistagged (e.g., a freshman-calc book
     mistagged as `dynamical_systems`) or legitimately marked but in-domain
     for that query.
   - If mistagged → fix the source tags; re-run eval.
   - If legitimately marked but in-domain → the marker semantics need
     domain-conditional logic (a source might be `low_redundant` for math but
     relevant for RL).
4. **Ground-truth re-grading IS the prerequisite for everything else.** Cost
   estimate: 500-1000 candidates with similarity ≥0.65 AND domain-match
   re-graded by human (~4-6h work). Without this, every eval-driven decision
   downstream rests on noisy labels (`feedback_eval_label_quality`).
5. **Build marker-stress-test queries** (separately from re-grading): write
   ~30 queries that intentionally pull from generic intro books / duplicate
   editions, with human-graded relevance. Without these, we cannot detect
   marker effects empirically.

**Order of operations** (revised from STRATEGIC_DIRECTION §6):
1. Re-grade existing pool's grade-0 chunks with similarity ≥0.65 (~4h human).
2. Investigate the dyn_sys/RL regressions; fix mistags or document
   domain-conditional marker semantics.
3. Re-run markers A/B on re-graded labels.
4. THEN decide: scale markers, retune multipliers, or remove them.
5. Marker-stress-test query addition can run in parallel with steps 1-3.

## 7. Methodology notes

- Eval ran on warm corpus (PG containers up 4+ hours; embed_server up since 07:26
  same day). Wall-clock ~22 min per run (markers-on 11:30→11:52, markers-off
  12:35→12:59). Per-query mean ≈ 18.6s, ~5x slower than memory's 3.4s/query
  baseline. Likely contributors: corpus size 1.37M→1.68M chunks, citation
  authority queries in `search_hybrid_v2`, possible cold caches between queries.
- `--save-run` enabled to preserve `run_dict` for `--compare` Fisher's randomization.
- Search config = `citations` (FTS+vector+citation, the production default).
  Graph = OFF (per `project_graph_defaults_unified`, KG re-extraction pending).
- Reranker = OFF (per `evaluation_runs/README.md:74`, BGE-reranker-v2-m3
  documented to *hurt* quality on this corpus).
